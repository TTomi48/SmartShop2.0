## AD-03 – Központi REST API-hibakezelés

**Dátum:** 2026-11-10  
**Állapot:** Implementálva, automatizált REST-tesztekkel ellenőrizve

### Probléma
A Service-ek különböző kivételeket dobnak, például `ResourceNotFoundException`, `DuplicateResourcesException` és `IllegalArgumentException`. Ezeket a REST API-nak megfelelő HTTP-státusszal és egységes JSON-válasszal kell visszaadnia.

### AI szerepe
Megkérdeztem az AI-t, hogyan lehet úgy kezelni a REST API hibáit, hogy a Controller-ekbe ne kerüljön üzleti logika vagy ismétlődő hibakezelés.

Az AI bemutatta a központi hibakezelés lehetőségét Spring Bootban, `@RestControllerAdvice` és `@ExceptionHandler` használatával. Ez számomra korábban nem ismert megoldás volt. Az implementáció kialakításában is AI-segítséget vettem igénybe.

### Megvizsgált megoldások
1. **Controller-enkénti `try-catch`:** egyszerű, de sok ismétlődő kódot eredményez.
2. **Kivételosztályokhoz rendelt HTTP-státuszok:** kevesebb kód, de kevésbé rugalmas a közös hibaválaszok kialakítása.
3. **Központi `GlobalExceptionHandler`:** egy helyen kezeli a kivételeket és a HTTP-válaszokat.

### Saját döntés
A **központi `GlobalExceptionHandler`** megoldást választottam.

**Indoklás:** A Controller-ek egyszerűek maradnak, nem kell minden végpontban külön hibakezelést írni, és az API egységes `{"error": "..."}` formátumú hibaüzeneteket ad vissza.

A megoldásban a `ResponseEntityExceptionHandler` öröklése a Spring által kezelt HTTP-kérési hibák egységesítését is segíti.

### Megvalósítás
A `GlobalExceptionHandler.java` a következő válaszokat kezeli:

- `ResourceNotFoundException`, `EntityNotFoundException` → HTTP 404
- `DuplicateResourcesException` → HTTP 409
- `IllegalArgumentException` → HTTP 400
- Hibás HTTP-kérés → megfelelő hibastátusz, egységes JSON-válasz
- Váratlan kivétel → HTTP 500, belső részletek nélkül

### Ellenőrzés
**Kód:** [GlobalExceptionHandler.java](../../backend/src/main/java/hu/bme/backend/exceptions/GlobalExceptionHandler.java)

A [RestApiTest.java](../../backend/src/test/java/hu/bme/backend/controllers/RestApiTest.java) MockMvc- és Mockito-tesztjei ellenőrzik a HTTP-státuszokat és az egységes JSON-válaszokat:

- `businessValidationReturns400`, `blankNameReturns400BeforeCallingTheService`, `missingRequiredFieldsReturn400`: hibás és hiányzó bemenet elutasítása.
- `missingAndMalformedBodiesReturnConsistent400Responses`, `invalidPathAndQueryTypesReturn400`: hiányzó vagy hibás JSON, illetve hibás típusú paraméterek kezelése.
- `missingStoreReturns404WithConsistentJson`, `missingEntityReturns404`: mindkét hiányzóerőforrás-kivétel kezelése.
- `duplicateResourceReturns409`: duplikáció kezelése.
- `unexpectedExceptionsDoNotExposeInternalDetails`: váratlan hiba esetén HTTP 500, belső részletek nélkül.

